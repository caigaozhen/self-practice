# 遥控小车 · uniapp 控制端

手机端用 uniapp 写，控制 ESP32 小车的前进、后退、转向和限速。

当前版本只做基础遥控：**摇杆控方向 + 滑块控限速 + 急停**。没有摄像头、没有录制、没有自动巡航。

---

## 一、先看这个：为什么不是 UDP

原方案规划的是 UDP，改用 uniapp 后必须换成 **WebSocket**，原因是三端能力不一样：

| 运行端 | UDP | TCP | WebSocket |
|---|:--:|:--:|:--:|
| H5（浏览器） | ✗ 浏览器没有 UDP API | ✗ | ✓ |
| App（5+ 运行时） | ✗ `plus.net.Socket` 只有 TCP | ✓ | ✓ |
| 微信小程序 | ✓ `wx.createUDPSocket` | ✓ | ✓ |

只有 WebSocket 三端通吃，而且 H5 端能在浏览器里直接调试，改一行代码刷新就能看效果，比装 APK 快得多。

代价是需要 ESP32 跑一个最小的 WebSocket 服务端（握手 + 帧解析），这部分已经写在 `firmware/main.py` 里了，你不用管。

## 三、怎么跑起来

### 用 HBuilderX（推荐）

1. HBuilderX → 文件 → 导入 → 从本地目录导入，选中 `car` 这个文件夹
2. 运行 → 运行到浏览器 → Chrome（H5，开发调试最快）
3. 手机调试时 → 运行到手机或模拟器 → 运行到 Android App 基座

## 四、通信协议

一条指令一帧 JSON 文本，30Hz 推送：

```json
{"y": 0.62, "x": -0.15}
```

| 字段 | 含义 | 范围 |
|---|---|---|
| `y` | 前后 | `1` 全速前进，`-1` 全速后退 |
| `x` | 左右 | `1` 全速右转，`-1` 全速左转 |

**限速在手机侧就乘进去了**，ESP32 收到的 `y` / `x` 就是最终值。好处是改限速逻辑不用重烧固件，坏处是 ESP32 不知道你设了多少限速——第一版不需要知道。

ESP32 收到后做差速映射：

```
左轮 = y + x
右轮 = y - x
```

推到右上角时 `y=0.6, x=0.6`，左轮 1.2、右轮 0，等比缩放后左轮满速右轮停转，车向右画弧。

## 五、操作说明

| 操作 | 效果 |
|---|---|
| 摇杆上推 | 前进，推得越远越快 |
| 摇杆下推 | 后退 |
| 摇杆左右 | 转向，配合前后可实现斜向行驶 |
| 摇杆推到底角落 | 一侧轮满速、另一侧慢，走出弧线 |
| 底部滑块 | 限速，20%~100%，控制整车的最高速度 |
| 急停按钮 | 立即停车并锁定，再点一次「解除」才恢复 |
| 松手 | 立即归零停车 |

**三个安全设计**：

1. **松手即停**——摇杆 touchend 直接归零，不会保持最后一帧
2. **急停锁定**——按下后强制发零速，摇杆被禁用，防止误触后车继续跑
3. **退到后台停车**——`onHide` 时发停车帧并停止推送，避免锁屏后车失控

ESP32 侧还有第四层：400ms 收不到指令就自动停车，覆盖手机断连、WiFi 抖动、App 被杀这些情况。

## 六、ESP32 端要做什么

```bash
# 1. 烧 MicroPython 固件（只做一次，参考上级目录 README）
esptool.py --chip esp32 --port COM3 erase_flash
esptool.py --chip esp32 --port COM3 write_flash -z 0x1000 ESP32_GENERIC-xxxx.bin

# 2. 上传服务端
mpremote connect COM3 fs cp firmware/main.py :main.py
mpremote connect COM3 reset
```

串口会打印：

```
AP: RC-CAR 密码: 12345678
WS: ws://192.168.4.1:81
```

手机连上 `RC-CAR` 热点（密码 `12345678`），打开 App 会自动连接。

### 浏览器测试台（不装 App 也能试车）

固件把网页和 WebSocket 塞进了同一个 81 端口：连接进来先看请求头，带 `Sec-WebSocket-Key` 的走 WebSocket，普通 HTTP GET 就返回内置的控制页。

手机浏览器直接打开：

```
http://192.168.4.1:81
```

会看到一个四方向按钮 + 限速滑块的测试页，页面自己再连 `ws://192.168.4.1:81` 发指令。**调试硬件阶段用这个比装 App 快得多**，改固件重新上传、刷新页面就能测。

注意两点：

- 这个页面的 `:active` 状态是按下变绿，松手恢复，按住才动、松手就停，和 App 逻辑一致
- 网页请求会占用一次连接，处理完立刻关闭，然后页面再发起 WebSocket 连接。所以**同一时间只能有一个控制端**，第二台设备连上来会排队

## 七、三端各自的坑

### H5（浏览器调试）

- 页面是 `http://` 时连 `ws://` 没问题；但如果页面部署到 `https://`，浏览器会拦截 `ws://`（混合内容），必须用 `wss://`。本地调试不用担心。
- 手机浏览器打开调试页时，要确认手机连的是小车热点，不是家里的 WiFi。

### Android App

- `manifest.json` 里已经加了 `INTERNET` 等权限，正常打包不用再改。
- 连上小车热点后系统会提示「此 WiFi 无法访问互联网」并可能自动切回 4G。**这里用字面 IP 地址访问，Android 会按子网路由走 WiFi，通常不受影响**。如果发现连不上，去系统 WiFi 设置里把这个网络设为「保持连接」。

### 微信小程序

- 开发者工具里要把「不校验合法域名」勾上，否则连 `ws://192.168.4.1` 会被拦。
- 真机预览必须连同一个热点。

## 八、常见问题

| 现象 | 原因 |
|---|---|
| 一直显示「未连接」 | 手机没连 RC-CAR 热点，或 IP/端口填错 |
| 显示已连接但车不动 | ESP32 的 STBY 没接 3.3V；或固件没启动 |
| 摇杆推了车延迟明显 | WiFi 信号弱，或 ESP32 主循环被串口打印拖慢（关掉 `DEBUG`） |
| 车忽快忽慢 | 电池电压下降，或电机干扰导致丢帧 |
| 松手后车还在跑 | 客户端的 touchend 没触发（页面滚动打断），检查 `disableScroll` 是否生效 |
| 急停点了没反应 | 检查 `firmware/main.py` 里 `TIMEOUT_MS` 是否被改大 |
| H5 打开一片空白 | HBuilderX 里 `main.js` 路径不对，确认用 Vue3 版本 |
