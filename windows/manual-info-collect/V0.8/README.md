# V0.8 · 配置界面与数据上报

> **一句话目标**：① 用 tkinter 做一个能改参数、能开关自启的配置窗口；② 把已结算的会话推到远端（HTTP 或 Supabase），并且重复推送不产生重复数据。

这一版是"打磨与扩展"，可以只做 ① 就停，也可以两件都做。建议按 8.1 → 8.2 的顺序。

## 8.1 配置界面（tkinter）

### 要做的事

| 区块 | 控件 | 落到哪 |
|---|---|---|
| 采集 | 采样间隔、空闲阈值、是否采标题 | `config.json` |
| 分类 | 进程名 → 分类的多行映射表 | `config.json` 的 `category_map` |
| 自启 | 一个复选框 + 灰字提示"当前已安装的命令" | 注册表（调 V0.2 的 `install/uninstall`） |
| 设备 | 本机显示名 | `config.json` |
| 状态 | 待上传条数、上次推送时间 | 只读展示 |

### 关键点

1. **GUI 必须在主线程**：tkinter 的 `mainloop()` 占住主线程，采集继续在自己的后台线程里跑。不要试图在子线程里创建控件。
2. **配置读写要原子**：先写 `config.json.tmp`，再 `os.replace()` 覆盖。直接覆盖写一半断电，配置就废了。
3. **校验先于保存**：数字字段先转 `int` 并检查范围，报错时把焦点定位到出错的输入框，而不是弹一个"保存失败"就完事。
4. **保存后热加载**：采集线程每轮检查 `config.json` 的 `mtime`，变了就重新读取参数——不用重启进程。
5. **首次运行**：配置文件不存在时，先弹配置窗，填完再进托盘。否则用户看到的是"双击了没反应"。

### 坑

| 坑 | 处理 |
|---|---|
| 在子线程里 `Tk()` | 崩溃或界面卡死，必须主线程 |
| 关窗没做 `destroy` | 进程退不掉（`mainloop` 还活着） |
| 中文输入法下回车键异常 | 绑定 `<Return>` 时区分控件类型 |
| 改完参数没生效 | 加 mtime 检测，或保存后主动通知采样线程 |
| 窗口置顶冲掉居中 | 先 `update_idletasks()` 再设 `-topmost`，或调整顺序 |

### 验收

- [ ] 改采样间隔并保存，不重启进程，日志里下一轮就用新值
- [ ] 关掉配置窗后进程仍在托盘运行
- [ ] 在界面上勾选/取消自启，注册表随之变化（`status` 可验证）
- [ ] 填非法数字（如 `abc`）时给出明确提示，且不写入文件

## 8.2 数据上报

### 协议最小集

```
POST <endpoint>
Content-Type: application/json
Authorization: Bearer <token>

{"client": "...", "device_id": "...", "sent_at": 1793355895,
 "sessions": [{"id": 12, "start_ts": ..., "end_ts": ..., "app": "..."}]}
```

### 四条必须遵守的规则

**① 推成功才标记已上传。**
`uploaded` 字段在服务端返回 2xx 之后才置 1。失败就留着，下次再推——**绝不丢数据**。

**② 幂等由主键保证。**
会话一旦结算就不可变，所以服务端按 `(device_id, id)` 做 upsert / `on conflict do nothing`。重复推送不会产生重复行。

> 如果服务端是 Supabase/PostgREST：直接 `POST /rest/v1/sessions` 配 `Prefer: resolution=ignore-duplicates` **会失败**，因为 `ON CONFLICT DO NOTHING` 需要 SELECT 权限，而客户端角色通常只有 insert。正解是写一个 `security definer` 的数据库函数，客户端调 RPC。

**③ 短超时，绝不阻塞采集。**
上报在独立线程里跑，`timeout` 5～10 秒。关机前的那次推送把超时压到 2 秒——Windows 关机只给几秒。

**④ 分批。**
一次最多 500 条，避免请求体过大被网关截断。

### 坑

| 坑 | 表现 | 处理 |
|---|---|---|
| 失败也标记已上传 | 数据永久丢失 | 只在 2xx 后标记 |
| 主键重复报 409 | 重推整批失败 | 服务端 upsert，或客户端忽略冲突码 |
| 字段为 `NULL` 违反非空约束 | `23502 null value in column` | 不采集的字段也要传空串，别省掉键 |
| 超时太长 | 关机被拖住 | 关机路径单独设短超时 |
| 上报线程未捕获异常 | 线程静默死掉 | V0.3 的 `threading.excepthook` |

### 验收

- [ ] 断网状态下推一次 → 本地数据仍在，`uploaded` 仍为 0
- [ ] 恢复网络后自动补推成功，条数正确
- [ ] 对同一批数据推两次，服务端行数不变（幂等）
- [ ] 关机时能在 2 秒内完成一次推送尝试，失败不阻塞关机
