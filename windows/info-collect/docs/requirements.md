## 1. 背景与问题

日常在 Windows 上工作，时间会被切成大量碎片：IDE、浏览器、聊天工具、文件管理器来回切换。
系统自带的「应用使用时间」粒度粗、不可导出、也无法回答「在 PyCharm 里具体写哪个项目」。

已有工具要么是云端 SaaS（数据不在自己手里），要么依赖重型框架（Electron / 第三方托盘库 /
数据库服务），对「只给自己用、长期常驻、离线可用」的场景过重。

因此本项目要做一个**本地优先**的时间去向记录器：

> 登录 Windows 后在后台静默运行，记录每个前台程序占用了多少时间、在干什么，
> 按类别汇总，随时能回答「今天时间花哪了」；可选同步到自建云端，用手机查看。

## 2. 干系人与使用场景

| 角色 | 说明 | 关注点 |
|---|---|---|
| 使用者（唯一） | 项目作者本人，在 1~N 台 Windows 电脑上使用 | 数据准确、常驻稳定、随时能看、隐私可控 |
| 开发者（同一人） | 维护采集端、手机端、云端脚本 | 零依赖、易打包、易排障、文档可追溯 |
| 间接相关方 | 手机端查看者（仍是本人） | 手机能按天、按设备看到汇总 |

典型使用场景：

1. 上班开机后自动开始记录，下班关机前自动收尾。
2. 想知道「今天编码 / 浏览 / 沟通各占多久」「哪个程序用得最多」。
3. 换一台电脑或移动程序目录后，仍能正确开机自启。
4. 出差时手机打开网页 / App，查看今天或昨天的汇总。
5. 发现某天数据缺失，能通过日志和心跳定位原因。

## 3. 范围

### 3.1 范围内

| 编号 | 能力 |
|---|---|
| S-01 | Windows 前台程序、窗口标题、键鼠闲置、锁屏状态采集 |
| S-02 | 会话化存储（连续工作合并为一段，切换/闲置/断档时结算） |
| S-03 | 分类映射与本地报表（文本 + 图形窗口） |
| S-04 | 托盘常驻、暂停/恢复、单实例、关机收尾 |
| S-05 | 配置界面与热更新 |
| S-06 | 开机自启（写当前用户注册表，不要求管理员） |
| S-07 | 可选上报（自建服务端 / Supabase），失败保留、启动补传、幂等 |
| S-08 | 手机端查看（uni-app，登录后按天/按设备查询） |
| S-09 | exe 打包交付（目标机不需要 Python）与版本标识 |
| S-10 | 日志、状态自检、数据清理等运维能力 |

### 3.2 范围外（明确不做）

| 项 | 原因 |
|---|---|
| 多用户 / 账号体系 / 权限后台 | 只给自己用，Supabase RLS 已足够 |
| 按键内容、剪贴板、文件内容采集 | 隐私边界，且无必要 |
| 浏览器 URL 精确解析 | 需要 UI Automation 或浏览器扩展，脆弱且成本高 |
| 跨平台（macOS / Linux） | 采集全部依赖 Win32 API |
| 应用商店上架、自动更新服务 | 非目标，交付形态是本地目录 + 手动升级 |
| 实时监控大屏 / 团队统计 | 单人工具，不做多租户 |
| 自动学习分类 | 当前用配置映射，新程序归入「其他」 |

## 4. 功能需求

优先级：P0 = 缺了就不能用；P1 = 日常必需；P2 = 增强。

| 编号 | 需求 | 优先级 | 验收要点 | 主要实现 |
|---|---|---|---|---|
| FR-01 | 周期采集前台程序、窗口标题、闲置时长、锁屏状态 | P0 | 默认 5 秒一次；拿不到数据不崩溃；中文标题不乱码 | `win/winapi.py` |
| FR-02 | 将连续活动合并为会话，切换/闲置/休眠断档时结算 | P0 | 切换不产生大量碎片；闲置结束时间回填到最后输入时刻；休眠不补记 | `win/sampler.py` |
| FR-03 | 按配置把进程名映射为分类 | P1 | 大小写不敏感；未命中归入 `default_category` | `win/classifier.py` |
| FR-04 | 本地 SQLite 持久化会话与元数据 | P0 | 强杀后残留会话下次启动自动补结算；WAL 模式可边跑边读 | `win/store.py` |
| FR-05 | 按天查看报表（分类占比、程序排行、明细） | P1 | 跨天会话按重叠时长计算；支持切换日期；无控制台时开窗口 | `win/reporter.py`、`win/ui_report.py` |
| FR-06 | 托盘常驻与菜单操作 | P1 | 托盘提示显示今日时长；支持暂停/恢复、报表、配置、推送、退出；重复启动被单实例锁拒绝 | `win/tray.py`、`win/app.py` |
| FR-07 | 图形化配置与校验 | P1 | 保存前校验字段范围；保存后 30 秒内热更新，不重启 | `win/ui_config.py`、`win/app.py` |
| FR-08 | 开机自启（仅当前用户） | P1 | 写入 `HKCU\...\Run`；优先使用 exe；能检测路径失效；启动时主动体检并支持一键修复（v0.3） | `win/autostart.py`、`win/app.py` |
| FR-09 | 本机标识与显示名 | P2 | 首次生成 12 位 device_id；显示名用于多设备区分 | `win/store.py`、`win/config.py` |
| FR-10 | 可选上报（定时 / 关机 / 启动补传 / 手动） | P1 | 推送成功才标记 uploaded；失败保留；不阻塞采集；关机推送短超时 | `win/uploader.py`、`win/sampler.py` |
| FR-11 | 上报幂等 | P1 | 重复批次不会造成云端重复行；服务端返回实际写入数 | `supabase/schema.sql` |
| FR-12 | 手机端查看 | P1 | 登录后按天查汇总；按设备筛选；token 过期可自动续期 | `mobile/src/pages`、`mobile/src/utils/api.js` |
| FR-13 | 状态自检与数据管理命令 | P2 | `status` / `cloud --ping` / `upload --dry-run` / `wipe` 可用 | `win/app.py` |
| FR-14 | exe 打包与版本标识 | P1 | `--onedir --windowed`；目标机无需 Python；exe 属性显示版本；交付目录含全部双击入口（v0.3） | `win/build_exe.bat`、`win/make_version_info.py` |
| FR-15 | 日志与故障可诊断 | P0 | 轮转日志（2MB × 3）；心跳可判断是否在跑；未捕获异常写入日志（v0.3） | `win/app.py`、`win/store.py` |

## 5. 非功能需求

| 编号 | 需求 | 指标 / 验证方式 |
|---|---|---|
| NFR-01 | 零第三方运行时依赖 | Windows 端只用 Python 标准库 + ctypes；`win/` 无 requirements.txt；打包仅需 PyInstaller |
| NFR-02 | 隐私可控 | 不采集按键内容；标题可整体关闭；默认不上传标题；数据只在本机 `%APPDATA%` |
| NFR-03 | 低开销 | 每 5 秒一次 API 采集；会话式存储约 200~800 行/天；一年数据量 < 5MB |
| NFR-04 | 可靠性 | 单实例锁；崩溃残留自动补结算；上报失败不丢数据；关机收尾尽力而为 |
| NFR-05 | 离线优先 | 断网、未配置云端时全部本地功能正常 |
| NFR-06 | 兼容性 | Windows 10 / 11；源码形态 Python 3.10+（开发用 3.14）；打包形态不依赖 Python |
| NFR-07 | 可用性 | 双击即用；配置全部在窗口内完成；首次运行默认勾选自启 |
| NFR-08 | 可维护性 | 模块单向依赖、无循环；SQL 只出现在 `store.py`；行为变更同步文档 |
| NFR-09 | 可交付性 | 交付物是整个 `dist\InfoCollect\` 目录；版本号单源于 `config.APP_VERSION` |

## 6. 关键业务规则

1. **闲置判定**：连续 `idle_threshold_seconds`（默认 300 秒）无键鼠输入，或检测到锁屏，即结束当前会话；
   结束时刻取「最后一次输入」而非「当前时刻」，避免把闲置时间算成工作。
2. **切换粘滞**：新程序需连续 `switch_confirm_samples`（默认 3）次采样才确认切换；
   切换时刻回填到新程序首次出现的时刻，既不丢时间也不重叠。
3. **工作单位**：编辑器类按标题首段切分；浏览器等 `app_level_apps` 内不按标题切分，避免碎片。
4. **代表标题**：一段会话只存出现次数最多的标题，不存逐秒快照。
5. **断档**：两次采样间隔超过 `max(3 × 间隔, 30 秒)` 视为休眠/挂起，结束在当前会话最后一次正常采样时刻，不补记。
6. **进行中会话**：`end_ts = 0`；程序启动时用 `last_heartbeat` 补结算，避免报表把「昨晚被强杀」算成「活跃 18 小时」。
7. **上报语义**：至少一次投递 + 云端 `(device_id, id)` 幂等，等效于不重不漏；本地只有收到 2xx 才置 `uploaded = 1`。
8. **单实例**：命名互斥体 `InfoCollect_SingleInstance`，防止开机自启与手动启动同时记录。

## 7. 主要用例

| 编号 | 用例 | 前置 | 主流程 | 结果 |
|---|---|---|---|---|
| UC-01 | 日常自动记录 | 已安装并开启自启 | 登录 Windows → 托盘启动 → 采样 → 切换/闲置时结算 | 本地库持续增长 |
| UC-02 | 查看今日时间去向 | 有采集数据 | 右键托盘 → 查看今日报表 → 分类/程序/明细 | 看到时长与占比 |
| UC-03 | 修改采集或上报配置 | 程序在运行 | 打开配置界面 → 修改 → 保存 | 30 秒内热更新 |
| UC-04 | 手机查看 | 已配置 Supabase 与登录用户 | 打开手机端 → 登录 → 选日期/设备 | 显示云端聚合 |
| UC-05 | 移动程序目录后修复自启 | 曾开启自启 | 移动 `dist\InfoCollect` → 启动新位置 → 托盘提示失效 → 点「修复」 | 注册表指向新路径 |
| UC-06 | 关机收尾 | 程序在运行 | 系统关机/注销 → 收到 `WM_QUERYENDSESSION` → 结算 + 短超时推送 | 会话有 end_ts，尽力上传 |
| UC-07 | 上报失败恢复 | 已开启上报，网络不可达 | 定时推送失败 → 数据保留 → 下次启动补传 | 最终上传成功 |

## 9. 约束与假设

- 仅支持 Windows 10 / 11，依赖 Win32 API（`GetLastInputInfo`、`GetForegroundWindow` 等）。
- 单用户、单实例；多台电脑各自一份本地库，通过 `device_id` 区分。
- 自启只写当前用户注册表，不需要管理员权限；因此对「以管理员身份运行的前台程序」可能拿不到进程名，
  此时记为 `unknown.exe`，不崩溃。
- 云端时区固定为 `Asia/Shanghai`；跨午夜会话在云端整段计入开始日，本地报表按重叠精确切分。
- 云端为可选组件；只有一个线上 Supabase 项目，无 dev/prod 分离。
- 默认采集窗口标题，可能包含文件名、聊天对象、网页标题等敏感信息；使用者需自行控制备份范围。
